# R2-3PO development requirements

These are the creator's project instructions, consolidated from the November 4,
2026 handoff. Preserve them across sessions. See `docs/development-continuity.md`
and the append-only `docs/manual-audit-log.md` for recovery and progress.

## Recover before editing

- Continue the latest verified development state, not an assumed `main` baseline.
  Inspect branches, draft PRs, commits, local changes and the current audit ledger.
- Reconcile historical handoffs with actual source and evidence. Historical plans
  and assistant reports are leads, not proof of implemented or tested behavior.
- Never rebuild real source from recollection or overwrite newer/more complete
  files with older copies. Investigate unexplained code disappearance.
- Preserve existing uncommitted work, features, integrations, personality,
  memories, source history and established layout. Trace apparently redundant
  code before changing it. Do not replace functioning systems with simpler demos.
- Finish disconnected/partial features through their real activation-to-outcome
  paths; an API, declaration or successful build does not establish functionality.

## Manual inspection is the work

Read actual source line by line in the scoped area; follow callers and callees.
Trace allocations and limits, ownership, lifetimes, synchronization, retries,
cancellation, cleanup, persistent writes and recall. Searches, compilation,
linting and tests supplement this work and cannot replace it.

Continue existing audit numbering. Record files/functions or line ranges, linked
paths, findings, changes, verification, commit, uncertainties and inspection
completion status. Distinguish a completed scoped trace from an audited whole
file or repository. Never infer subsystem completeness from passing CI.

Do meaningful sustained workloads without manufacturing work or rushing review.

## Information integrity

- Do not silently shorten conversations, transcripts, source IDs, memories,
  journals, responses, files or relevant context to bypass engineering problems.
- Fix capacity, allocations, storage, streaming or processing design. Limits must
  have an explicit justification and avoid unintended loss. Rejecting incomplete
  data is a guard, not proof the full processing feature is complete.
- Distinguish observed events, reports, real actions, verified outcomes,
  hypotheses, imagined outcomes and uncertainty. Hypotheticals must not become
  factual experiences. No invented observations or success claims.
- Typed/spoken sentences use the same established conversation semantics without
  duplicate turns or fabricated user messages. Keep private reasoning, control
  requests, tool results and outward replies separate. Verify real action results
  before updating memory or reporting success. Preserve execution validation.

## Preserve autonomy and sensory provenance

R2's creator is his mother within his established identity. Preserve identity,
learned relationships, developmental history and evolving choices/preferences;
do not replace these with a fixed response table or continually reduce ordinary
conversation to AI/robot labels. Character goals are not proof of consciousness.

Perception and attention are separate. Sources may be available, capturing,
processed, attended to or causing a response; do not conflate these states.
Keep microphone, separate desktop outputs, real camera and media independently
identifiable. Preserve provenance through capture, transcription, persistence
and recall. Do not mix sources into an indistinguishable stream or hardcode
speech/noise to interrupt a movie. R2 chooses what to investigate or ignore.
Preserve voluntary camera/media attention and existing activation requirements.

Inspect discovery, activation, ownership, workers, hotplug/switching, blocking
reads, decoder lifecycle, cancellation, restart and long-running operation.
Capture APIs alone are not continuous-perception acceptance.

## Git workflow and reports

- Work on isolated development/audit branches. Continue an appropriate latest
  branch or branch from its verified state; preserve all relevant files.
- Make reviewable incremental commits and push completed work. Keep PRs draft.
- Do not modify/merge into `main` or merge any PR without creator authorization.
- Run applicable strict build/regression checks, investigate failures and record
  their exact code heads/results. No claimed test without actual evidence.
- Distinguish creator baseline, source inspection, static checks, compilation,
  synthetic/runtime integration, physical-host and long-duration acceptance.
- Report branch/HEAD, draft/push status, untouched `main`, scoped files/paths,
  actual fixes, tests/results, missing acceptance, audit position and exact next
  work. Preserve an accurate continuation record.
- Respect established decisions; avoid repeated approval/questions, unsolicited
  redesigns and new features. Ask only genuinely unresolved nuanced questions.
